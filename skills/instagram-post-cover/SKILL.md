# Instagram 게시물 커버

실제 선정 사례를 보고, 주제와 맞는 웹 소재에 짧고 읽히는 제목을 편집한다. 일반적인 카페 감성이나 앱 광고 배너로 해석하지 않는다.

## 절대 규칙: 웹 소재만 사용

- **이미지 생성 금지.** ImageGen/image_gen, text-to-image, img2img, diffusion, 생성형 채우기, 인페인팅·아웃페인팅, AI 배경·인물·물체 생성/교체를 호출하지 않는다. 외부 서비스나 서브에이전트에 우회 위임하지 않는다.
- **모든 사진·일러스트·질감 소재는 웹에서 실제 파일을 가져온다.** 선정된 참고 게시물은 스타일 연구용이며 새 게시물의 원본 소재로 재사용하지 않는다. 사용자가 소재를 첨부해도 출처를 확인한다. 웹 원본이 없으면 임의로 웹 출처를 만들어 붙이지 않는다.
- 소재가 부족하면 다른 검색어·웹 출처·구도를 찾는다. 생성 이미지나 가짜 사진을 대체품으로 넣지 않는다. 확보하지 못하면 누락 소재와 진행 가능한 범위를 알린다.
- 다운로드한 이미지의 크롭·리사이즈·회전·명도/색상 조절, 글자·단색 면·선·가독성 그라디언트 배치와 PNG/JPEG 출력은 허용한다. Pillow/SVG/HTML/CSS/Figma로 하는 **결정론적 조판**은 이미지 생성 모델 사용과 구분한다. 없는 장면을 합성하거나 사진 속 사실을 바꾸지 않는다.
- 텍스트형은 실제 선정 사례에 포함된다. 사진이 불필요한 텍스트형에 가짜 시각 소재를 만들 필요는 없다. 직접 입력한 제목과 기본 도형은 웹 이미지 의무의 대상이 아니다.
- 사진 게시물·캐러셀 첫 장만 대상으로 한다. 릴스/영상 커버는 제외한다. 참고 이미지에 보이는 재생·캐러셀 아이콘은 Instagram UI이므로 디자인에 복제하지 않는다.

## 작업 순서

### 1. 주제와 레퍼런스 선택

사용자의 주제·타깃·원하는 산출물·기존 Figma 프레임을 우선한다. 부족한 정보는 가능한 맥락으로 결정하고, 제작을 막는 정보만 질문한다.

[유형별 가이드](references/playbook.md)에서 적합한 유형을 고른다. 제작 전에 **해당 유형의 통과 이미지 2–4장을 실제로 열어 본다.** 필요하면 탈락 사례도 함께 비교한다. 파일 이름만 보고 디자인하지 않는다.

```bash
python3 scripts/list_references.py --family photo-headline --limit 6
python3 scripts/list_references.py --ids b02-132,b02-274,b02-006
```

경로는 이 스킬 폴더 기준이다. 명령은 참고 게시물 URL을 출력한다. 공개 패키지는 타 계정의 이미지 파일을 재배포하지 않는다. 출력된 원문 링크를 열어 이미지를 확인한다. 로그인·삭제 등으로 접근할 수 없으면 본 것처럼 말하지 말고, 접근 가능한 다른 사례를 찾는다. 그래도 부족하면 유형 가이드에 근거한 제작임을 밝히고 진행한다. 추가 열람 도구의 권한을 우회하지 않는다.

전체 선정 판단과 출처는 [catalog.json](references/catalog.json), 표본의 범위와 해석 한계는 [evidence.md](references/evidence.md)를 참조한다.

통과 여부는 사용자 판단이다. 유형 태그·레이아웃 권장값은 에이전트의 해석이다. 탈락 이유를 사용자가 말했다고 꾸미지 않는다. 선정된 게시물의 주장·뉴스·인용문을 사실 검증된 문구로 취급하지 않는다.

### 2. 웹에서 원본 소재 확보

웹 이미지 검색이나 전용 커넥터로 찾고, **원본 페이지를 열어 실제 출처와 이미지의 관련성을 확인한 뒤 다운로드**한다. 검색 결과 썸네일 주소만으로 출처 확인을 끝내지 않는다. 가능하면 공식 보도자료·브랜드 자료·제작자 원문·적절한 라이선스 자료를 우선한다.

선정 레퍼런스의 얼굴·내용을 그대로 복제하는 대신 새 주제에 맞는 이미지를 찾는다. 저해상도 이미지를 AI 업스케일하거나 배경을 생성해 늘리지 않는다. 다른 해상도나 크롭을 선택한다.

작업 폴더의 `sources.json`에 각 사용 이미지의 `id`, `origin: web`, `source_page_url`, `image_url`, `accessed_at`, `credit`, `usage_basis`, `local_path`, `sha256`, `operations`를 기록한다. URL은 실제 확인한 값만 쓴다. 공개 접근 가능과 재사용 허용을 혼동하지 않고, 확인하지 못한 이용 조건은 `unknown`으로 남긴다. 워터마크를 지우거나 타인의 커버를 로고만 바꿔 사용하지 않는다.

뉴스·숫자·제품 효능·인용을 제목에 쓸 경우 원문으로 확인한다. 짧고 강한 제목을 위해 허위 사실, 허위 추천, 조작한 대화 캡처를 만들지 않는다. 웹에서 찾은 이미지도 AI 생성물로 명시되어 있으면 실제 사진인 것처럼 사용하지 않는다.

### 3. 후킹 문구와 조판

핵심 제목은 한 가지로 정하고 2–3개의 짧은 문구 후보 중 주제와 이미지가 가장 잘 연결되는 것을 택한다. 사용자에게 후보 선택을 반드시 기다릴 필요는 없다.

기존 프레임이 없으면 1080×1350을 작업 시작 크기로 삼을 수 있다. 이는 디자인 기본값이며 최신 플랫폼 규격을 검증했다는 뜻이 아니다. 게시 규격 준수가 별도 요구면 공식 자료를 확인한다.

선택 유형의 구도·줄바꿈·대비를 따라 만들되 원본 커버를 그대로 베끼지 않는다. 글자 크기와 크롭을 먼저 맞춘 뒤 장식을 넣는다. 브랜딩은 작게, 제목은 피드에서 읽히게 한다. 링크 버튼·파란 CTA 띠·설명문 덩어리로 웹 랜딩페이지처럼 구성하지 않는다.

Figma 수정 요청이면 관련 Figma 스킬의 필수 절차를 따른다. 파일 산출물 요청이면 편집 가능한 레이아웃과 PNG/JPEG를 만든다. 어떤 도구를 쓰든 생성형 이미지 기능은 금지한다.

### 4. 출력 검사와 전달

최종본과 가로 약 270px의 피드 미리보기를 실제로 열어 검사한다.

- 피사체/핵심 오브젝트와 제목이 작은 크기에서도 구별되는가?
- 제목의 한 가지 핵심이 읽히고, 줄바꿈이 의미 단위를 보존하는가?
- 얼굴·제품·글자가 의도치 않게 잘리지 않고 대비가 충분한가?
- 사진에 없던 장면·허위 내용·불필요한 UI 아이콘이 추가되지 않았는가?
- 사용 이미지 전부에 웹 출처·다운로드 파일·해시가 남아 있는가?
- 실제 선택한 통과 사례와 비교했는가? 금지된 생성/생성형 편집을 사용하지 않았는가?

결과 파일, 핵심 소재의 출처 링크, 선택한 레퍼런스 ID를 간결하게 전달한다. 편집본과 `sources.json`을 함께 보관한다. 조회수·탐색 상위 노출·알고리즘 성과를 보장하지 않는다.
